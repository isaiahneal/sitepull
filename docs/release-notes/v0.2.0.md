# Sitepull v0.2.0

Sitepull 0.2.0 makes capture completeness visible, transient failures recoverable, repeated work faster, and native release provenance independently verifiable.

## Highlights

- Retryable navigation failures receive up to three attempts with bounded exponential backoff and `Retry-After` support. Every attempt is preserved as structured evidence instead of disappearing behind a final success or failure.
- Browser response bodies now use three coordinated default limits: 25 MiB per resource, 512 MiB across one capture, and three concurrent body reads. Bytes from a failed page attempt are rolled back before a retry.
- The desktop Overview reports page and resource coverage, recovered pages, HTTP-error resources, element truncation, inaccessible stylesheet rule lists, failed routes, and bounded URL decisions. `AI_CONTEXT.md` carries the same coverage signal into an AI Pack.
- Recent captures are searchable by host or URL. New captures retain their complete effective recipe, and **Capture Again** preloads that recipe—including output parent, URL fallback policy, viewports, and crawl limits—for review before a fresh run.
- The global CLI installer deploys a complete versioned runtime under per-user application data, so `sitepull` no longer depends on the source checkout remaining in place.
- The renderer reconciles live capture state with a bounded main-process event snapshot on load and focus, merging events by capture ID and sequence.
- Design analysis now preserves valid negative margins as signed spacing tokens without relaxing nonnegative constraints for radii or non-margin spacing.
- HTTP 4xx documents remain failed-route evidence instead of entering design analysis. Explicit source maps are streamed through the capture budget with redirect-by-redirect public-network validation, including bracketed and IPv4-mapped IPv6 protection.
- DNS validation is pinned into the browser/source-map sockets that actually connect. Non-proxied WebRTC and WebTransport paths are disabled; WebKit page workers are disabled because worker WebTransport can bypass an HTTP proxy.

## Release integrity

The tagged distribution workflow cannot begin native packaging until the reusable quality workflow passes and the tag exactly matches `package.json` plus a nonempty versioned release-notes file. External workflow actions are pinned to immutable commits. On each native runner, Sitepull verifies the expected installer/archive outputs, hardened Electron fuse state, embedded Playwright WebKit launch, and packaged renderer startup. macOS additionally checks the bundle's internal ad-hoc signature consistency.

The Ubuntu 24.04 DEB declares the embedded WebKit runtime libraries. Before publication, it is installed and fully smoke-tested with Chromium's sandbox enabled on the native Ubuntu runner. The same DEB is independently clean-installed in a digest-pinned Ubuntu 24.04 container, where the workflow audits its dependency closure, executable layout, embedded WebKit launcher, and root-owned `4755` `chrome-sandbox` helper. Sitepull does not publish a generic Linux ZIP because an archive cannot safely establish those sandbox-helper permissions, and it does not publish an RPM in v0.2.0 because the Ubuntu-targeted WebKit binary requires ABI versions unavailable from current Fedora repositories.

Before GitHub Release publication, the workflow creates and re-verifies an exact `SHA256SUMS.txt`, then records Sigstore-backed GitHub build-provenance attestations for each native artifact and the checksum manifest. Verify a downloaded artifact with:

```bash
gh attestation verify ./Sitepull.dmg \
  --repo isaiahneal/sitepull \
  --signer-workflow isaiahneal/sitepull/.github/workflows/distribution.yml
```

Build provenance does not replace publisher identity. These community artifacts are still not signed with Apple Developer ID or Microsoft Authenticode, macOS hardened runtime and notarization remain unconfigured, and Linux packages are not distributed through a signed repository.

## Compatibility and boundaries

- Existing `v0.1.0` captures and history remain readable. Legacy page manifests have no retry-attempt array, and legacy recent entries have no saved recipe.
- Responsive screenshots resize one stabilized page through the configured viewports. DOM and computed-style extraction still reflects the first configured viewport; initial-load behavior selected by viewport requires a separate capture.
- Responses without a trustworthy content length still require Playwright to materialize one complete response buffer before Sitepull can enforce its actual size.
- Sitepull continues to capture public browser-delivered output only. It does not recover private source repositories or bypass authentication, CAPTCHAs, paywalls, anti-bot controls, or private-network restrictions.

## Install

Download the native package for your platform from this release, or build from source and install the global CLI:

```bash
pnpm install:cli-global
sitepull --version
sitepull pull example.com --headless --ai-pack --zip
```

The CLI and generated capture metadata both report Sitepull `0.2.0`.
