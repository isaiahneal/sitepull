# Sitepull v0.5.0

Sitepull 0.5 adds deliberate outbound routing controls to both the desktop app and headless CLI. Captures can use one proxy or rotate across a pool, apply bounded connection jitter, and override the browser User-Agent string without weakening Sitepull's existing private-network boundary.

## Proxy routing

Pass `--proxy` once for a fixed endpoint or repeat it to create a pool:

```bash
sitepull pull example.com \
  --headless \
  --proxy http://proxy-a.example:8080 \
  --proxy https://proxy-b.example:8443 \
  --proxy-selection round-robin \
  --proxy-jitter 250:1250
```

Use `--proxy-selection random` for randomized selection. Selection and jitter occur per new outbound connection; browser keep-alive can carry multiple resources over one connection. A configured proxy pool is fail-closed—Sitepull never silently falls back to the machine's direct network.

Proxy URLs must use `http://` or `https://` and contain only an authority. Sitepull rejects embedded credentials, paths, query strings, fragments, SOCKS, PAC files, and implicit system/environment proxy discovery.

### Authentication

Keep proxy passwords out of argv, literal shell-history entries, and process listings. Number credentials by the order of repeated `--proxy` flags. This Bash/Zsh example reads one pair interactively without echoing the password:

```bash
printf 'Proxy 1 username: '
IFS= read -r SITEPULL_PROXY_1_USERNAME
printf 'Proxy 1 password: '
IFS= read -rs SITEPULL_PROXY_1_PASSWORD
printf '\n'
export SITEPULL_PROXY_1_USERNAME SITEPULL_PROXY_1_PASSWORD

sitepull pull example.com \
  --proxy https://proxy-a.example:8443

unset SITEPULL_PROXY_1_USERNAME SITEPULL_PROXY_1_PASSWORD
```

Repeat the numbered pair for additional authenticated proxies. For a single proxy, the unnumbered `SITEPULL_PROXY_USERNAME` and `SITEPULL_PROXY_PASSWORD` aliases are also accepted. Sitepull requires complete username/password pairs and removes these variables from its own process environment before launching the browser. The parent shell retains exported variables, so unset them after the command as shown.

Basic authentication is Base64 encoding, not encryption. Use `https://` for authenticated proxy endpoints; an `http://` proxy exposes its authorization header to observers on the client-to-proxy network path.

The desktop Advanced Settings panel provides the same proxy pool, selection, jitter, and per-endpoint authentication controls. Proxy endpoints and whether authentication is required are saved for **Capture Again**. Usernames and passwords remain only for the current capture/retry session, are cleared on success or when leaving that flow, and must be re-entered later.

## User-Agent override

The CLI accepts a manual string:

```bash
sitepull pull example.com --user-agent 'Sitepull-Compatible-Browser/1.0'
```

The desktop app provides Browser default, desktop/mobile browser presets, and a Custom field. The resolved string is saved in capture metadata and the capture recipe so later runs remain reproducible.

This is intentionally described as a User-Agent string override, not full fingerprint impersonation. In Chromium, User-Agent Client Hints and related platform surfaces can still identify the actual engine.

## Network-policy preservation

User proxies are chained behind Sitepull's loopback policy proxy:

```text
Browser -> Sitepull policy proxy -> selected upstream proxy -> validated destination
```

Sitepull continues to resolve each destination locally, reject private or mixed address sets, and pin the validated numeric destination. The upstream proxy receives that numeric destination rather than being asked to resolve the target hostname. Browser HTTP(S), WebSocket traffic, redirects, and explicit source-map downloads use the configured upstream path. Proxy Basic authorization is added only to the outer proxy connection and is never forwarded to the destination.

Proxy credentials are excluded from recipes, recents, manifests, `sitepull.json`, AI context, structured logs/events, errors, AI Packs, and Full Capture archives. Authentication, CAPTCHA, paywall, and access-control bypass remain out of scope; HTTP 403 responses remain terminal rather than causing identity cycling.
