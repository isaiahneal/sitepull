# Sitepull v0.4.1

Sitepull 0.4.1 turns the GitHub release into a guided install instead of asking each user to identify, verify, and install the right package by hand.

## Quick install

macOS or Linux:

```bash
curl -fsSLo /tmp/sitepull-install.sh \
  https://github.com/isaiahneal/sitepull/releases/latest/download/sitepull-install.sh
sh /tmp/sitepull-install.sh
```

Minimal Alpine installations can use `wget` when `curl` is not installed:

```sh
wget -qO /tmp/sitepull-install.sh \
  https://github.com/isaiahneal/sitepull/releases/latest/download/sitepull-install.sh
sh /tmp/sitepull-install.sh
```

Windows PowerShell:

```powershell
irm https://github.com/isaiahneal/sitepull/releases/latest/download/sitepull-install.ps1 `
  -OutFile "$env:TEMP\sitepull-install.ps1"
powershell -NoProfile -ExecutionPolicy Bypass `
  -File "$env:TEMP\sitepull-install.ps1"
```

The shell installer detects macOS 15+ on Apple silicon or Intel and the exact supported Ubuntu, Debian, Fedora, or Alpine release on x64. The PowerShell installer requires Windows x64. Unsupported operating systems, release versions, and architectures stop with an explicit compatibility error before a package is downloaded.

Use `--dry-run` (PowerShell: `-DryRun`) to inspect the package selection without network or filesystem changes. Use `--version 0.4.1` (PowerShell: `-Version 0.4.1`) to pin this release instead of resolving the latest stable release.

## Native installation behavior

- **macOS 15+ arm64/x64:** verifies the architecture-matched DMG and installs `Sitepull.app`
- **Ubuntu 24.04 x64:** verifies the distribution-matched DEB and installs it with APT
- **Debian 12/13 x64:** verifies the distribution-matched DEB and installs it with APT
- **Fedora 44 x64:** verifies the native RPM and installs the global headless-only `sitepull` CLI with DNF
- **Alpine 3.24 x64:** verifies both the native APK and release-specific public key, installs the key, and installs the global headless-only `sitepull` CLI with APK
- **Windows x64:** verifies `SitepullSetup.exe` and waits for the Squirrel installer to complete

The macOS, Ubuntu, Debian, and Windows packages install the desktop application. The Fedora and Alpine packages install the headless CLI globally at `/usr/bin/sitepull`; they remain Chromium-only and reject `--headed`.

## macOS package seal correction

The release build now removes AppleDouble `._*` sidecars before the final ad-hoc application seal. The native smoke gate mounts the finished DMG and runs strict deep signature verification against the app inside the image, closing a gap where the unpacked application could pass while DMG creation omitted a sealed sidecar. The quick installer independently verifies both the in-image app and its staged copy before replacing an existing installation, and its signal-safe cleanup restores the prior app after an interrupted cutover.

## Release integrity

Both installer scripts are first-class release assets. The tagged workflow requires the exact fourteen native artifacts plus the two installers before it creates `SHA256SUMS.txt`. It then verifies all sixteen payload digests, records GitHub/Sigstore build-provenance attestations, uploads the draft, and compares the final GitHub names and digests byte-for-byte before publication. Including `SHA256SUMS.txt`, the public release contains exactly seventeen files.

Each installer resolves one immutable release tag, downloads only the expected asset names from `github.com/isaiahneal/sitepull`, and verifies the selected package against the exact-name SHA-256 entry before invoking the operating system's installer. The bootstrap script itself is delivered over HTTPS and is separately covered by the release checksum and provenance attestation; inspect it before running or verify it with GitHub CLI when your threat model requires bootstrap authentication.

These community builds are not signed with Apple Developer ID or Microsoft Authenticode and are not distributed through a persistent signed Linux repository. GitHub attestations establish the source workflow and exact bytes; they do not replace operating-system publisher identity.

The CLI and generated capture metadata report Sitepull `0.4.1`.
